General Usage Guide

Master application security.

RedPatch is an interactive learning platform that allows you to safely exploit, analyze, and patch vulnerable applications in isolated Docker containers.

01 / EXPLOITTest realistic vulnerabilities.
02 / ANALYZEUse AI to understand flaws.
03 / PATCHFix code dynamically.

Coder Mode vs. Pentester Mode

RedPatch offers two distinct modes of engagement to accommodate different learning objectives:

Coder Mode

In Coder Mode, your primary task is defense. Using the built-in code editor in the Workspace, modify target files to patch security vulnerabilities. After patching, you can trigger AI Analysis to confirm if your fix is correct and secure.

Pentester Mode

In Pentester Mode, you take on the offensive role. The goal is to discover and exploit the vulnerability within the application to retrieve a hidden flag. Submit the discovered flag in the Workspace input field to pass the lab.

Playing Labs

Navigate to the Modules page to explore available vulnerability categories like SQL Injection (SQLi), IDOR, and Command Injection. Select a specific lab to begin.

  • Launch: Clicking launch will download the lab image if not already cached, and spin up an isolated Docker container for your session.
  • Proxy: Lab applications are proxied securely through RedPatch, giving you immediate web access to the vulnerable app.
  • Flags: Use the application to find hidden flags (e.g., redpatch{...}) which prove successful exploitation of the vulnerability. Submit these flags in the Workspace to verify your exploit.

Workspace & AI Integration

Once a lab is running, enter the Workspace. The workspace provides an IDE-like environment to view vulnerable code files and apply patches.

  • Code Editor: Modify the target files to implement security patches. The container dynamically applies your changes.
  • AI Analysis: If you're stuck, click "Analyze with AI". RedPatch's integrated AI Agent will review the code and provide detailed insights on the vulnerability and potential fixes.
  • Hints & Solutions: Access step-by-step hints or view the official solution file if you need immediate guidance.
  • Reset: If you break the application, use the Reset Lab feature to destroy the container and start fresh.
Developer Guide

Local Setup

The host application runs on FastAPI, managing lab lifecycles via Docker. Make sure Docker Desktop or the Docker daemon is running before starting the development server.

# Create and activate a virtual environment
python -m venv .venv
pip install -r requirements.txt
uvicorn app.main:app --reload

To enable the AI Analysis features, you must configure a .env file in the root directory with the necessary API keys defined in app/core/config.py.

The Manifest System

RedPatch uses a centralized app/labs/manifest.json to catalog available modules. Labs are downloaded as Docker image archives and extracted automatically.

{
  "labs": {
    "SQLi": {
      "description": "SQL Injection vulnerabilities.",
      "submodules": [
        {
          "id": "sqli-0",
          "title": "Auth Bypass",
          "category": "web",
          "image_tag": "redpatch-lab/sqli-0:v1.0.0",
          "port": 5000,
          "download_url": "http://host.docker.internal:4444/sqli-0.tar"
        }
      ]
    }
  }
}
FieldDescription
idUnique identifier for the lab (used for URLs and container names).
image_tagDocker image tag to load and run.
portInternal TCP port the lab listens on.
download_urlURL to the .tar or .tar.gz image archive.

Lab Image Architecture

Labs are distributed as standard Docker images. RedPatch extracts the /app directory from the image to use as the workspace volume.

  1. Your lab Docker image must contain an /app directory.
  2. It must include a /app/main.py which acts as the entrypoint for Uvicorn/FastAPI based labs.
  3. It must contain a /app/config.json that defines the workspace targets, hints, and flags.
Important: RedPatch extracts the source tree to allow patching, and mounts it into the container at runtime. Never hardcode absolute host paths.

Workspace Configuration (config.json)

Inside your lab's /app directory, the config.json defines how the RedPatch Workspace interacts with the lab code, dividing configuration for both coders and pentesters.

{
  "hints": {
    "target_snippet.py": [
      "Do not pass raw user input directly to shell execution functions.",
      "Use safe alternatives or validate/sanitize input against a strict allowlist."
    ],
    "pentester": [
      "Check how the input is handled in the ping command execution.",
      "Try appending command separators like ';' or '&&' followed by a system command."
    ]
  },
  "solutions": {
    "solution_snippet.py": "codes/solutions/solution_snippet.py",
    "pentester": "127.0.0.1 && cat /app/flag.txt"
  },
  "targets": {
    "target_snippet.py": "codes/vulnerables/target_snippet.py"
  },
  "flags": {
    "flag_1": "redpatch{command_injection_rce_compromised_xxxxx}"
  }
}
  • targets: Maps display filenames to relative paths in the workspace. These files become editable.
  • hints: Contains arrays of hints for target files (Coder Mode) and a separate pentester array of hints (Pentester Mode).
  • solutions: Contains solution file mappings (Coder Mode) and a pentester exploit payload string (Pentester Mode).
  • flags: Defines flags the user must find to prove exploitation.
