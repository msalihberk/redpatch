Open-source contribution guide

Build safe, useful RedPatch labs.

This guide covers the current module contract, local workflow, and review expectations for contributors. Keep every lab educational, self-contained, reproducible, and limited to systems you own or are authorized to test.

01 / ISOLATEDUse fictional data and local containers.
02 / REPRODUCIBLEMake vulnerable and fixed flows testable.
03 / FOCUSEDKeep one security lesson per lab.

Run the project locally

The host application uses FastAPI; individual labs run in Docker. Install the root dependencies and start the development server. Docker must be running before launching a lab from the workspace.

# Create and activate a virtual environment for your shell
python -m venv .venv
pip install -r requirements.txt
uvicorn app.main:app --reload

AI analysis also requires the environment variables used by app/core/config.py, including API_KEY. Never commit a .env file or credentials.

Module system

RedPatch scans app/modules. A category is registered by its own config.json; its labs live in the category's submodules directory.

app/modules/
└── SQLI/
    ├── config.json
    └── submodules/
        └── BASIC_SQLI/
            ├── config.json
            ├── main.py
            ├── requirements.txt
            └── codes/
                ├── vulnerables/
                └── solutions/
FieldRule
nameNon-empty and unique. Names are normalized to uppercase.
runtimeDocker image used to run the lab, such as python:3.11-slim.
entrypointPython file whose stem is loaded by Uvicorn. main.py must expose app.
internal_portPositive TCP port used inside the lab container.
codesMaps editable file names to their role.

Create a new lab

  1. Create a category under app/modules, or select an existing category.
  2. Create submodules/<SUBMODULE> and add its application, dependencies, templates, and code samples.
  3. Register the lab in the parent category configuration.
  4. Confirm that it appears in the Modules page, starts in Docker, and supports both vulnerable and fixed flows.
{
  "name": "SQLI",
  "description": "Training labs for SQL injection vulnerabilities.",
  "sub_modules": [{
    "name": "BASIC_SQLI",
    "description": "Authentication bypass caused by SQL string concatenation.",
    "runtime": "python:3.11-slim",
    "entrypoint": "main.py",
    "internal_port": 5000,
    "codes": { "target_snippet.py": "vulnerable" }
  }]
}
Important: the runner creates a session-specific copy of the lab and starts uvicorn <entrypoint-stem>:app. It does not build the submodule's Dockerfile. Put needed Python packages in the lab's requirements.txt.

Workspace contract

The codes map also authorizes workspace patches. Each key is a file name that must occur only once in the submodule. Files marked vulnerable are shown in the editor; configure hints and reference fixes in the submodule's own config.json.

{
  "hints": { "target_snippet.py": ["Use parameter binding."] },
  "solutions": { "target_snippet.py": "codes/solutions/solution_snippet.py" }
}

Quality, safety, and pull requests

  • Use fictional, non-sensitive data and keep exploits inside the target container.
  • Do not hard-code host ports; RedPatch maps the internal port automatically.
  • Test module discovery, the workspace, container startup, reset behavior, and both lesson outcomes before submitting.
  • Keep pull requests focused and explain the lesson, expected behavior, and validation steps.
